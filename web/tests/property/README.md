# spec.md 6.1 プロパティテスト

フェーズ2 手順⑤で作成し、人間の承認後に保護フォルダ `web/tests/property/` へ移動した。変更は人間の承認が必要（CLAUDE.md の保護対象）。

- `properties.ts`: 8 件のプロパティ。検査対象の実装（`Impl`）を引数に取る。
- `impl.ts`: 本物の実装と、1 か所だけ壊した実装（ミュータント）。
- `spec61.test.ts`: 各プロパティが (a) 本物の実装で成り立ち、(b) ミュータントでは反例が見つかることを確かめる。

3 手法（ヒストリカル・ブートストラップ・パラメトリック）すべてを検査する。ヒストリカルは N ≤ 0 なら計算しない（`null`）ので対象外。
入力は、実質リターン −40〜+60% の 10〜40 年の系列、期間 1〜40 年、初期資産 100〜10,000、生活費は初期資産の 0〜20%、信託報酬 0〜2%、パス数 100。

| # | 内容 | 検査のしかた | 壊すと失敗する例 |
|---|---|---|---|
| 1 | 生活費を増やしても成功率は上がらない | 同じリターン列で生活費 2 つを比べる | 成功判定を反転 |
| 2 | 初期資産を増やしても成功率は下がらない | 同じリターン列で初期資産 2 つを比べる | 成功判定を反転 |
| 3 | 生活費 0 なら成功率 100% | 前提: 全パス・全年で `1 + r_real − fee > 0`（満たさない入力は `fc.pre` で除外） | 「最終残高 ≥ 初期資産」を成功とする |
| 4 | 期間 0 なら成功率 100% | 生活費を初期資産の 0〜3 倍にしても 100%。前提は期間 0 では自明 | 期間 0 でも期初に取り崩しの判定をする |
| 5 | 一定リターンで閉形式と一致 | `B_T = B0·g^T − S·(g + g² + … + g^T)`、`g = max(0, 1 + r − fee)`。途中で破産する入力は除外。許容誤差は式の各項の大きさの 1e-9 倍 | 取り崩しを運用の後にする / 信託報酬を足す |
| 6 | 同一シード・同一入力で完全一致 | 2 回生成・計算し、成功数・破産年・全残高をビット単位で比較 | 呼ぶたびにシードがずれるブートストラップ |
| 7 | 為替 0 なら JPY = USD | 為替変化率 0、日米インフレを同一にした合成データで、実質リターン系列と結果が完全一致 | JPY でインフレ調整を忘れる |
| 8 | 信託報酬を増やしても成功率は上がらない | 成功率に加え、各パスの最終残高も増えないことを検査（成功率だけでは 0〜2% の差で反例が出にくいため） | 信託報酬を足す |

補足:

- 4 の「生活費 ≤ 0 かつ初期資産 > 0」のうち、生活費 0 は 3 で検査する。負の生活費はエンジンの入力検証で拒否する（2章: 生活費 ≥ 0）。
- 倍率が 0 になる場合（`1 + r_real − fee ≤ 0`）は、全損した年の後は残高 0 で破産扱いとする（spec.md 7章 決定済み 12）。3・4 はこの場合を前提で除外する（決定済み 13）。
- ミュータント検査は `fc.check` のシードを固定して再現できるようにしている。本物の実装の検査はシードを固定しない。
