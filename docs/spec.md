- 版: 0.7（期間が共通期間より長い場合の扱いを決定）

- 変更履歴: v0.2（2026-09-29, 人間の指示）標本不足の注意表示・出所表示を追加。v0.3（同日, 人間の指示）データ出典を Damodaran・FRED・総務省統計局に整理。v0.4（同日, 人間の指示）投資対象を `SP500` と `GOLD` に整理。v0.5（同日, 人間の指示）`WORLD_DM`（先進国株式）を JST データベースで追加。v0.6（同日, 人間の承認）7章「決定済み（v0.6）」を追加。v0.7（同日, 人間の承認）7章「決定済み（v0.7）」に N ≤ 0 の扱いを追加。

## 1. 目的とスコープ

初期資産・FIRE期間・年間生活費・投資対象を入力すると、資産が期間終了まで残る確率（成功率）を、
モンテカルロ法と過去の実データで算出し、直感的に可視化する。

**スコープ外（v1）**: 税金、年金・社会保障、取り崩し戦略の最適化、任意配分、アカウント/保存機能、サーバー通信。

## 2. 入力

| 項目 | 型・範囲 | 既定値 | 備考 |
|---|---|---|---|
| 通貨 | `USD` / `JPY` | `JPY` | 表示と換算の両方に影響 |
| 初期資産 | 数値 > 0 | 5,000万円 | 通貨に応じた単位 |
| FIRE 期間 | 整数 1〜60 年 | 30 | |
| 年間生活費 | 数値 ≥ 0 | 200万円 | 期初に取り崩し。**実質**（今の物価）額 |
| 投資対象 | `SP500`（S&P500）/ `WORLD_DM`（先進国株式）/ `GOLD`（ゴールド） | `SP500` | v1 は単一資産。`WORLD_DM` は先進18か国の等ウェイト合成で、時価総額加重の指数ではない |
| 信託報酬（年率） | 0〜2 % | 0.1 % | 任意 |
| 手法 | ヒストリカル / ブートストラップ / パラメトリック | 全手法を並列表示 | |
| パス数 | 10,000（固定、上級設定で最大50,000） | 10,000 | |
| シード | 整数 | 固定値（再現性表示） | |

バリデーションはすべてクライアント側で行い、不正値は実行せずエラーを表示する。

## 3. 計算モデル

### 3.1 共通

- 単位は年次。年ごとに `期初に生活費を取り崩し → 残高に年次リターンを適用` の順。
- リターンは**実質**（名目リターンを当該国のインフレ率で調整）。
  - USD: 名目USDリターンを米国CPIで調整。
  - JPY: `(1+USDリターン)×(1+USD/JPY変化率)−1` を日本CPIで調整。
- 信託報酬は年率を実質リターンから差し引く。
- **破産**: 取り崩し後の残高が 0 以下になった時点（以降の残高は 0 固定）。
- **成功**: 期間終了時に残高 > 0。
- 成功率 = 成功パス数 / 全パス数。ヒストリカル手法では成功開始年数 / 全開始年数。

### 3.2 手法

| 手法 | 内容 |
|---|---|
| ヒストリカル | 利用可能な各開始年から期間分の実際のリターン列を再現。開始年数が少ない場合は 4章の注意表示（項目9）を出す。 |
| ブロック・ブートストラップ | 過去の年次リターンを、ブロック長 3 年（既定）で復元抽出。相関・連続下落を部分的に保持。 |
| パラメトリック | 対数リターンを正規分布（平均・標準偏差は過去データから推定）で生成。 |

### 3.3 データ

- 系列と出典（出所表記は 4章 項目10）:
  - `SP500`: Aswath Damodaran（NYU Stern）の年次リターン表（S&P500・配当込み、名目USD）。1928 年〜。
  - `WORLD_DM`: Jordà-Schularick-Taylor Macrohistory Database（Release 6）の先進18か国の株式総合リターン（現地通貨建て、年次）を、同データの対米ドル為替で USD 建てに換算し、各年の等ウェイト平均として合成（有効な国が10か国以上ある年のみ）。**1950 年〜2020 年**（データベースの最終年まで）。ライセンスは CC BY-NC-SA 4.0（非営利・継承。加工後の `returns.json` も同条件）。
  - `GOLD`: 同じ Damodaran の年次リターン表の金（名目USD）。1971年8月の金兌換停止までは公定価格のため、**1972 年〜**のみ使用。
  - 米国CPI: FRED CPIAUCNS（米国労働統計局、月次、1913年〜）。
  - USD/JPY: FRED DEXJPUS（日次、1971年〜）。年次変化は 12月最終営業日の値どうしの比。
  - 日本CPI: 総務省統計局「消費者物価指数（CPI）」（総合、月次）。
- 年次化: 資産リターンは暦年（前年12月→当年12月）。インフレ・為替は Dec/Dec。データが年末まで揃わない年は使わない。
- 検証: Damodaran の表のインフレ列を FRED CPI 由来のインフレと突き合わせ、年のずれを検出する。
- 配信するのは年次リターン等の加工済み JSON のみ（`data/processed/`）。生データは配信しない。
- 各系列の出典・ライセンス・加工方法は `data/processed/SOURCES.md` に記載。**再配布不可の系列は使わない**。ライセンス状態は `pipeline/src/fire_data/config.py` で管理し、配信前に `validate --strict` で検査する。
- 通貨・資産の組み合わせで共通期間が短い場合、その期間を画面に表示する。

## 4. 出力

1. **成功率（％）**: 最も大きく表示。色と言葉で段階表示（例: 90%以上 / 75〜90% / 75%未満）。単独の色だけに意味を持たせない。
2. **ファンチャート**: 資産推移の 10 / 25 / 50 / 75 / 90 パーセンタイル。
3. **スパゲッティ図**: サンプルパス最大 200 本。破産パスを強調表示。
4. **破産年の分布**: ヒストリカルまたは選択手法のヒストグラム。
5. **手法比較**: 3 手法の成功率を並べて表示。
6. **逆算**: 「成功率 90% を満たす年間生活費の上限」を二分探索で表示。
7. **前提の表示**: 使用データ期間、通貨、実質ベース、手法、シード、パス数。
8. **免責**（常時表示）: 「本アプリは教育・情報提供目的で投資助言ではありません。過去の実績は将来を保証しません。税金・年金・手数料の一部は考慮していません。為替の影響を含みます（JPY選択時）。」
9. **標本不足の注意表示**: ヒストリカル手法の開始年数 N（= 選択資産（と通貨）で使える連続年数 − FIRE期間 + 1）が小さいときに表示する。
   - N < 20: 「過去実績の標本が少ないため、参考程度に見てください」を成功率の近くに表示。
   - N < 10: 強い注意表示に切り替え、ヒストリカルの成功率に「参考値」ラベルを付ける。
   - 開始年の窓は重なっているため、独立な標本の数は N よりさらに少ないことを文言に含める。
   - 注意表示が出ているときは、成功率の大表示の代表値を**ブートストラップ法**にし、3手法の値（項目5）を必ず併記する。
   - 例: `GOLD`（1972〜2025年）・50年は N = 5（強い注意）。`WORLD_DM`（1950〜2020年）・30年は N = 42。閾値（20 / 10）は暫定値で、フェーズ2で妥当性を見直す。
10. **データ出所・加工表記**（常時表示。フッター等）: `returns.json` の `attribution.notice_ja` を、内容を変えずに表示する。使用した出典すべての出所と、「各種計算結果は開発者が独自に加工したもので、各提供元が作成・公表したものではない」旨、日本CPI使用時は統計局の出所と加工の旨（`validate` が検査）を含む。

## 6. 受け入れテスト（オラクル）

実装は以下をすべて満たすこと。**これらは保護対象**。

### 6.1 プロパティ（`web/tests/property/`）

1. 年間生活費を増やしても成功率は上がらない（単調非増加）。
2. 初期資産を増やしても成功率は下がらない（単調非減少）。
3. 生活費 0 のとき成功率 100%。
4. 期間 0 相当（または生活費 ≤ 0 かつ初期資産 > 0）のとき成功率 100%。
5. ボラティリティ 0・一定リターン `r` のとき、残高は閉形式解（年金現価の式）と一致。
6. 同一シード・同一入力で結果が完全一致。
7. **為替変化率が全期間 0 のとき、JPY の結果は（インフレ以外が同一なら）USD と一致**。
8. 信託報酬を増やしても成功率は上がらない。

### 6.2 ゴールデン（`web/tests/golden/` ⇔ `golden/`）

- Python リファレンスが出力した固定ケース（入力・シード・成功率・パーセンタイル）と、TS 実装が許容誤差内で一致。
- 許容誤差: 成功率 ±0.5 ポイント（10,000 パス以上）、決定的手法（ヒストリカル）は完全一致。

### 6.3 既知結果（サニティ）

- S&P500 相当の実質リターン・30 年・4% ルール相当で、Trinity Study 系の既知の成功率（おおむね 9 割超）と大きく乖離しない。許容範囲はフェーズ2で確定し、根拠を ADR に残す。

### 6.4 表示要件（E2E）

- 選択した資産・期間で N < 20 のとき、注意表示が出る。N < 10 のとき強い注意表示と「参考値」ラベルが出る。N ≥ 20 のときは出ない。
- 成功率の近くに 3 手法の値が併記される。
- `attribution.notice_ja` が画面に表示され、テキストが `returns.json` と一致する。

### 6.5 非機能ゲート

第 5 章の各基準を CI で自動検証する（バンドルサイズ、計算時間、axe、Lighthouse）。

3. 逆算探索の成功率目標値を UI で変更可能にするか。
4. Trinity Study サニティの許容範囲。

### 決定済み（v0.6, 2026-09-29, 人間の承認）

以下は 3章・4章の計算仕様を補う。

1. **代表手法**: 成功率の大表示は、注意表示の有無にかかわらず常に**ブロック・ブートストラップ**の値とする。3手法の値は常に併記する。
2. **逆算**: 代表手法（ブートストラップ）で行う。乱数から作るリターン列は生活費によらず固定し（同じシードで1回だけ生成）、生活費だけを変えて二分探索する。目標成功率は 90%。
3. **信託報酬と残高倍率**: 各年の残高倍率は `max(0, 1 + r_real − fee)` とする（`r_real` は 3.1 の実質リターン、`fee` は年率の信託報酬）。取り崩し後の残高にこの倍率を掛ける。
4. **ブロック・ブートストラップ**: 循環ブロック・ブートストラップとする。共通期間の年次実質リターン列（長さ `n`）について、ブロックの開始位置を `0〜n−1` から一様に選び、`n` を超えた位置は先頭に戻る（`mod n`）。ブロック長を `L`（既定 3）、期間を `T` とすると、1パスにつき `ceil(T / L)` 個のブロックを順に選んでつなぎ、先頭 `T` 年分を使う。**`T` が `L` の倍数でない場合は、最後のブロックの末尾を切り捨てる**（例: `T = 31, L = 3` なら 11 ブロックを選び、最後のブロックは先頭 1 年分だけを使う）。
5. **パラメトリック**: 共通期間の実質リターン（信託報酬を引く前）の `ln(1 + r_real)` の標本平均と標本標準偏差（自由度 `n−1`）を使う。生成した `r = exp(z·σ + μ) − 1` に 3 の式で信託報酬を適用する。
   - 正規乱数は Box–Muller 法で作る。一様乱数 `u1, u2` を**この順に**引き、`R = sqrt(−2 ln(1 − u1))`、`θ = 2π·u2` として `z0 = R·cos θ`、`z1 = R·sin θ` を作る（`u` は `[0, 1)` なので `1 − u1` は 0 にならない）。**`z0` と `z1` の両方を、この順で使う**。正規乱数はパス 0 の 1 年目〜T 年目、パス 1 の 1 年目〜T 年目…の順に消費し、ペアはパスの境目をまたいでよい。正規乱数の総数が奇数の場合、最後の `z1` は捨てる。
   - TS と Python は同じ手順で乱数を消費する。ただし `log`・`cos`・`sin` の実装差があるため、パラメトリックのゴールデンは完全一致ではなく**許容誤差**（6.2）で比較する。
6. **パーセンタイル**: 各年末（年 0〜T）の残高について、NumPy の既定（線形補間）と同じ方法で計算する。破産パスは残高 0 として含める。
7. **サンプルパス（スパゲッティ図）**: ブートストラップ・パラメトリックはパス番号の先頭から最大 200 本を表示する。**ヒストリカルは全パス（全開始年）を表示する**。
8. **ゴールデンの許容誤差**（6.2 を補う）: パーセンタイル等の数値は、ヒストリカルは完全一致、ブートストラップは相対誤差 1e-9 以内、パラメトリックは相対誤差 1e-6 以内。成功率はいずれの手法も ±0.5 ポイント以内（ヒストリカルは 6.2 のとおり完全一致）。
9. **逆算の探索**: 年間生活費の探索範囲は `0〜初期資産`。区間の幅が初期資産の 1e-4 倍未満になった時点で打ち切り、成功率が目標以上となる側の端を結果とする。

### 決定済み（v0.7, 2026-09-29, 人間の承認）

10. **期間が共通期間より長い場合（N ≤ 0）の扱い**: FIRE期間 T が、選択した資産（と通貨）の共通期間の年数より長い場合、ヒストリカル手法は計算しない（結果は `null`）。画面には、ヒストリカルの成功率の代わりに「過去実績が不足」と表示する。ブートストラップとパラメトリックは計算し、表示する。このとき 4章 項目9 の強い注意表示（N < 10）を出し、成功率の大表示は代表手法（ブートストラップ）とする。T が共通期間の年数と同じ場合は N = 1 で、ヒストリカルは計算する（強い注意表示と「参考値」ラベルが付く）。
