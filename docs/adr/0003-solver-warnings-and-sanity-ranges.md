# ADR-0003: 逆算・集計・注意表示の補足決定とサニティ範囲

## 決定（2026-09-29, 人間の決定）

決定 2 の `capped` フラグは、下書き作成後に人間が決定した（同日）。

1. **逆算で解がない場合は `null`**。生活費 0 でも代表手法の成功率が目標（90%）未満なら、逆算の結果は `null`（該当なし）とする。
   倍率 0 で全損するパス（`spec.md` 7章 決定済み 12）が 10% を超える場合に起こりうる。
   - 下端（生活費 0）を先に判定する。このため、成功率関数が単調でなく、下端で目標未満・上端で目標以上となる場合も `null` になる。
2. **生活費 = 初期資産でも目標以上なら初期資産を返す（上限で頭打ち = capped）**。探索範囲 `[0, 初期資産]` の上端で目標を満たす場合は、二分探索をせずに初期資産を返す。
   これは T = 0 のときだけ起こる（T ≥ 1 では、生活費 = 初期資産なら 1 年目の取り崩し後の残高が 0 で破産する）。UI の入力は 1〜60 年なので、通常は起きない。
   - 結果は `capped` フラグを持つ。上端（初期資産）を返した場合は `true`、それ以外は `false`。頭打ちは `spending === 初期資産` ではなく、このフラグで判別する。
3. **破産年の分布では、T 年目に全損したパスを別枠で数える**。T 年目に倍率 0 で全損したパスは、破産を翌年に扱うため（`spec.md` 7章 決定済み 12）、エンジン上の破産年を持たない。成功でもない。
   このようなパスは、年 1〜T の破産数とは別に「期間終了時に残高 0」（`endedAtZero`）の件数として返す。破産数の合計 + `endedAtZero` + 成功数 = 全パス数。
4. **注意表示の文言**（`spec.md` 4章 項目9 を補う）。文言は `warnings.ts` の `WARNING_TEXTS` に集約する。`{N}` には実際の開始年数が入る。
   - 注意（10 ≤ N < 20）: 「過去実績の標本が少ないため、参考程度に見てください。開始年の期間は互いに重なっているため、独立な標本の数は開始年の数（{N}）よりさらに少なくなります。」
   - 強い注意（1 ≤ N < 10）: 「過去実績の標本が非常に少ないため、ヒストリカルの成功率は参考値です。開始年の期間は互いに重なっているため、独立な標本の数は開始年の数（{N}）よりさらに少なくなります。」ヒストリカルの成功率に「参考値」ラベルを付ける。
   - N ≤ 0: 「過去実績が不足しているため、過去実績方式は計算できません。ブートストラップとパラメトリックの結果をご覧ください。」ヒストリカルの成功率の代わりに「過去実績が不足」と表示する。「参考値」の語は使わない。

## 追加の決定（2026-09-29, 人間の決定。手順⑦の Python 参照実装の作成時）

決定 5 は `docs/golden-cases.md` の記載を補うもの。決定 6〜8 は参照実装で曖昧さが見つかり、人間が決めた。

5. **ゴールデンの比較方法**: 数値の相対比較は `|a − b| ≤ rel · max(|a|, |b|)`（両方 0 なら一致）。逆算の `successRate` は ±0.5 ポイント。
   ケースは 24 件（A 6 + B 4 + C 4 + D 1 + E 6 + F 3）。ケース JSON の構造（キー名は camelCase、`input`・`output`・`tolerance` の中身）は `docs/golden-cases.md` の「ケース JSON の構造」に定め、TS 側のテストはこれを読む。
6. **逆算の `evaluations`**: 成功率を計算した回数をすべて数える。下端（生活費 0）と上端（初期資産）の判定も含める。
   capped なら 2、通常は 2 + 二分探索の中点の回数。結果が `null` のときは `evaluations` を出さない。
7. **T = 0 の N**: 式 N = 共通期間の年数 − T + 1 を特別扱いせず、N = 共通期間の年数 + 1 とする。
   ヒストリカルは開始年 0〜N−1 の N 通りで、最後の開始年の窓は空（全パス成功）。例: USD_SP500（98 年）では 99 通り（ゴールデン B4）。UI の入力は 1〜60 年なので、通常は起きない。
8. **パラメトリックで `r_real ≤ −1` を含む系列**: `ln(1 + r_real)` が定義できないため、入力検証で拒否する。Python 参照実装は `ValueError` を出す。
   現在の配信データでは起きない（実質リターンの最小値は −0.565）。`spec.md` 7章 決定済み 5 への追記候補（`spec.md` は未変更）。

## 補足（実装上の性質）

- 逆算の二分探索は、区間の端の条件（下端は目標以上、上端は目標未満）だけを使う。リターン列を固定すれば、成功率は生活費について単調非増加になる（各パスの残高が生活費について単調非増加のため）。
  単調でない成功率関数では、返す点は目標以上だが上限とは限らない。この挙動は単体テストで固定している。
- パーセンタイルは NumPy の `percentile(method='linear')` と同じ演算順で計算する（重み γ ≥ 0.5 のときは上側から引く式）。
