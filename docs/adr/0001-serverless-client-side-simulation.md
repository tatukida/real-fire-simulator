# ADR-0001: シミュレーションをクライアント側で実行し、Firebase Hosting（Spark）で静的配信する

- 状態: 採用
- 日付: 2026-09-29

## 背景

- 公開ポートフォリオであり、アクセス増や不正アクセスがあっても**料金が増えない**ことが必須。
- Python バックエンドを置くには Cloud Functions 等が必要で、Blaze（従量課金）プランが要る。Blaze の予算アラートは通知のみで自動停止しない。
- 計算量は 1万〜5万パス × 最長60年程度で、ブラウザで十分に実行できる。

## 決定

1. モンテカルロ計算は Web Worker 上の TypeScript で実行する。
2. 配信は Firebase Hosting（Spark プラン）の静的ファイルのみ。Spark は上限到達時にサービスが止まるハードキャップ方式で、課金が発生しない。
3. Firestore / Auth / Storage / Functions / Analytics は使わない（Blaze 必須または攻撃面の増加を避けるため）。
4. Python はオフラインで使う: データ整備と、NumPy によるリファレンス実装（TS 実装の検証用オラクル）。

## 結果・トレードオフ

- 利点: 運用費0円、攻撃面が小さい、二重実装による品質保証をポートフォリオとして示せる。
- 欠点: 転送量の上限（目安：約10GB/月。要・公式確認）に達するとその日は停止しうる。→ 初回ロードを軽量化し、強いキャッシュを設定し、バンドルサイズをCIゲートにする。
- 欠点: 二重実装の保守コスト。→ ゴールデンテストで乖離を自動検出する。

## 代替案

- Cloudflare Pages（帯域無制限・無料）: 技術的には有力だが、Firebase 利用の意向により見送り。停止時の予備としてGitHub Pagesへ移行可能。
- Pyodide（ブラウザ内Python）: 初回ロードが重いため見送り。将来の検討課題。
